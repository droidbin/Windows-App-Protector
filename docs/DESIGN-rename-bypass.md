# 실행 파일 이름 변경·복사 우회 설계

## 위협

- 현재 IFEO 규칙은 실행 파일 이름을 기준으로 동작한다.
- 보호된 `sample.exe`를 다른 이름으로 바꾸거나 복사하면 같은 파일이어도 IFEO Gate를 거치지 않을 수 있다.
- 공격자는 보호 앱의 실행 파일에 읽기 권한이 있고 다른 위치에 파일을 만들 수 있다고 가정한다.
- 이번 단계에서는 이 우회를 문서화하며, 2.0.0-alpha.4에 새 프로세스 감시 기능을 넣지 않는다.

## 선택지

1. **ETW 프로세스 시작 이벤트**
   - 서비스가 커널 프로세스 이벤트를 받아 실행 경로를 정규화하고 파일 해시와 정책을 비교한다.
   - 지연이 짧고 WMI보다 이벤트 손실·부하를 통제하기 쉽다.
   - 차단 결정 시점에는 프로세스가 이미 시작됐으므로 일시 중지·종료와 사용자 안내 설계가 필요하다.
2. **WMI `Win32_ProcessStartTrace`**
   - 구현과 진단이 비교적 단순하고 구형 Windows에서도 사용할 수 있다.
   - 이벤트 지연, 공급자 재시작, 짧게 실행되는 프로세스 누락 가능성이 ETW보다 크다.
3. **경로·SHA-256·선택적 서명자 일치**
   - 원래 경로는 정상 실행의 빠른 판정에 쓰고, 다른 경로는 해시로 동일 파일인지 확인한다.
   - 업데이트로 파일이 바뀌면 해시 재승인 정책이 필요하며, 해시 계산 중 파일 교체(TOCTOU)를 고려해야 한다.
4. **파일 시스템 미니필터**
   - 실행 전 차단에는 유리하지만 커널 드라이버 개발·서명·배포·복구 부담이 크다.
   - 개인용 무서명 제품 범위와 맞지 않으므로 제외한다.

## 권장 접근

- 서비스에 ETW 기반 프로세스 시작 감시를 추가하고 WMI는 진단용 대체 수단으로만 검토한다.
- 정책에는 정규화한 원본 경로와 SHA-256을 저장한다. 동일 경로는 파일 ID와 해시 캐시를 사용하고, 이름·경로가 달라지면 해시를 다시 계산한다.
- 보호 파일과 해시가 같으면 프로세스를 즉시 일시 중지하거나 종료한 뒤, 대화형 세션의 Gate에 PIN 흐름을 요청한다.
- 승인된 실행은 서비스가 만든 짧은 수명의 세션별 토큰으로 감시기가 한 번만 통과시킨다.
- 해시가 바뀐 정상 업데이트는 관리자 UI에서 명시적으로 재승인하며 자동 신뢰하지 않는다.

## 위험

- 이벤트 도착 전에 프로세스가 코드를 실행하는 시간차가 남는다.
- 대형 파일 해시 계산은 시작 지연과 디스크 부하를 만들 수 있다.
- 런처·자체 업데이트·다중 프로세스 앱은 부모/자식 및 승인 토큰 연결이 복잡하다.
- 보호 파일을 읽을 수 없거나 네트워크 경로인 경우 실패 정책을 정해야 한다.
- 다중 세션, 관리자·표준 사용자, 서비스 재시작 중 이벤트 손실을 별도로 처리해야 한다.

## 시험 계획

1. 원본 이름·원본 경로, 이름 변경, 다른 폴더 복사, 동일 이름의 다른 파일을 각각 실행한다.
2. 경로가 달라도 해시가 같은 파일만 PIN 대상으로 판정되는지 확인한다.
3. 취소·오답·정답, 허용 시간, 종료 후 재잠금이 기존 IFEO 흐름과 동일한지 확인한다.
4. 파일 업데이트·실행 직전 교체·잠긴 파일·대형 파일에서 판정과 오류 문구를 확인한다.
5. 빠른 단명 프로세스, 자식 런처, 동시 실행, 서비스·감시기 재시작과 이벤트 손실을 시험한다.
6. Windows 10/11 x64와 관리자·표준 사용자·다중 세션에서 CPU·디스크·시작 지연을 기록한다.
