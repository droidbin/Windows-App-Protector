## 2. 사용자 지시와 유효한 작업 범위

- 사용자는 “이 앱은 별도 승인없이 깃허브에 바로 릴리즈해”라고 승인했다. 요청된 릴리즈의 커밋·푸시·게시·배포 파일 검증에 재승인을 반복해서 묻지 않는다.
- 마지막 배포 지시는 “마무리하고 별 문제 없으면 정식 릴리즈해”였다. 미검증을 성공으로 간주하지 않았고, 정식판은 보류한 채 beta.6을 공개했다.
- **Windows 11은 현재 사용자 PC의 Admin 계정**, **Windows 10만 VM**에서 시험한다. 이 지시는 앞선 Windows 10·11 공유 VM 시험 지시보다 최신이다.
- 공유 환경은 SMB Manager가 사용하던 시험 환경이다. 사용자는 **“SMB 시험 종료 후 순차 진행”**을 선택했다. 현재 SMB 작업 완료와 VM 작업 상태를 확인하고, 진행 중인 시험·서비스·계정·체크포인트를 보존한다.
- 클린 Windows 11 복제 VM에서의 설치 UI 시험은 사용자가 **보류**했다.
- Windows 11 Admin의 기존 PIN을 앱에 직접 입력해 달라는 요청에도 사용자는 **“현재 입력하기 어려움”**이라고 답했다. PIN을 추측·초기화·우회하거나 채팅으로 요구하지 않는다. 전체 PIN 이후 UI 회귀는 미완료다.
- 기존 사용자 설정, 보호 앱, PIN, GitHub 릴리즈·태그·자산은 보존한다. 공개한 beta.6의 바이트를 교체하지 않는다. 추가 수정은 새 버전으로 배포한다.
- 관리자 권한 악성코드까지 방어한다고 보장하지 않는다.

## 3. 완료한 기능과 버그 수정

### 잠금 시 보호 앱 종료

- `CloseAppsOnLock` 설정 추가, 기본값은 꺼짐.
- 켜면 대상 Win32 앱의 **전체 실행 파일 경로**로 프로세스를 찾아 `CloseMainWindow()`로 정상 종료 요청 후 5초 대기한다.
- 응답하지 않거나 종료를 거부한 앱은 제품 코드에서 강제 종료하지 않는다. 잠금은 적용하고 종료 실패를 안내한다.
- 패키지/MSIX 앱은 정상 종료 대상에서 제외한다.
- 개별 잠금, 전체 잠금, 유휴 자동 잠금 경로를 연결했다.
- 중요한 수정: `CloseRunningAppsAsync`에서 현재 `app.Enabled`로 대상을 거르지 않는다. 개별 잠금 대상은 아직 `Enabled=false`일 수 있기 때문이다. 호출자가 잠글 앱 목록을 전달하며 유휴 경로도 종료 후 잠금 상태를 적용한다.
- 저장하지 않은 작업 손실 가능성을 설정 UI에서 안내한다.

### 방어·복구

- UI가 종료돼도 Windows 서비스가 공유 설정에 따라 IFEO 규칙을 주기적으로 복구한다.
- SCM 서비스 실패 복구는 5초 지연 재시작 3회로 설정돼 있다.
- 창 감시가 보호 창을 숨길 때 일상적인 상태 메시지를 덮어쓰지 않도록 수정했다. 종료 거부 안내가 유지된다.

### 설치·업그레이드

- 새 payload를 임시 폴더에 풀고 필수 파일과 실제 WinUI 실행을 검증한 뒤 기존 버전을 제거한다.
- 새 `--verify-install` 실행 모드는 메인 UI나 사용자 설정을 열지 않고 WinUI 컨트롤 생성과 런타임 초기화를 확인한 뒤 종료한다. 설치 프로그램은 최대 20초 기다리고 실패 시 기존 설치를 제거하지 않는다.
- 기존 설치 레지스트리 및 기본/레거시 `.old` 폴더를 탐지하고, 제거 경로·알려진 WAP 파일·재분석 지점 등을 검증한다.
- 기존 WAP 프로세스·서비스·등록·시작 작업·바로가기·설치 폴더를 정리하고 새 버전을 설치한다. PIN·설정·보호 앱 목록은 보존한다.
- beta.5에서 확인된 런타임 부재 오류 `0x80008083`에 대응해 **.NET 8.0.32 x64 + Windows App SDK 2.0.1을 앱에 포함**하는 자체 포함 배포로 변경했다.
- `build_setup.ps1`은 일반 빌드 폴더 대신 `dotnet publish` 결과를 패키징한다. 단일 EXE 번들 방식은 사용하지 않는다.
- 주의: SDK 호환 문제 때문에 `RuntimeFrameworkVersion`을 전역 속성으로 지정하지 않고 `FrameworkReference Update="Microsoft.NETCore.App"`의 메타데이터로 8.0.32를 지정했다. 전역 지정 때 Windows SDK 참조 패키지를 8.0.32로 잘못 복원하려는 오류가 있었다.

### 접근성·설치 앱 검색

- 작업·아이콘 버튼 9개에 명시적인 접근성 이름을 부여했다.
- 추가 시험 로그에서 설치 앱 검색의 `System.Text.Json.JsonException`을 발견해 수정했다. PowerShell이 명시적 UTF-8 압축 JSON 배열을 콘솔 출력 스트림에 직접 쓰고 C#도 UTF-8로 읽도록 했다.
- Windows 11 Admin의 실제 검색 서비스는 249개 유효 항목을 3회 연속 반환했다.
- UI Automation에 노출되는 행 수는 가상화 등의 영향을 받는다. 초기 44행, 최종 스냅샷 37행을 관찰했다. 이를 전체 설치 앱 수나 고정 통과 기준으로 사용하지 않는다.

## 7. 미완료 검증과 정식 릴리즈 조건

정식 릴리즈는 아직 하지 않았다. README에는 안정판 게시 전 Windows 빌드, 업데이트 해시, 설치/업그레이드 및 재부팅 동작을 확인하도록 기록돼 있다. 남은 우선순위:

1. 사용자가 보류한 클린 설치 UI 시험을 재개할 수 있는지 확인. 런타임 부재 환경에서 UI까지 성공했다고 주장하지 않는다. 자체 포함 파일·설정·실행 검사 및 기존 PC 설치 성공과 구분한다.
2. Windows 10 VM에서 WAP 전용 재부팅·자동 시작·서비스/규칙 복구 검증. SMB 작업 종료와 공유 환경 보존을 확인한 뒤 진행한다. 기존 SMB의 재부팅 기록을 WAP 시험으로 대체하지 않는다.
3. Windows 11 Admin에서 사용자 PIN 인증 이후의 전체 UI 회귀. 현재 사용자 부재를 이유로 PIN을 변경하지 않는다. 실제 사용자 PC 재부팅은 작업 영향부터 확인한다.
4. 온라인 업데이트 전체 과정. 자산 다운로드·해시 검증 성공과 앱의 업데이트 설치 전체 성공을 구분한다.
5. 실제 미저장 문서의 저장 확인창, 다른 사용자/권한 수준, 브라우저·창 감시·다중 창, 패키지 앱 차단, 실제 키보드 단축키, 절전/복귀, 유휴 경계값, 화면 레이아웃 등을 범위에 맞게 검증한다.

정식판을 만들 때 공개 beta.6을 안정판으로 이름만 바꾸거나 기존 파일을 교체하지 않는다. 버전 문자열·설치 경로·패키지·문서를 안정판에 맞춰 새로 빌드·검증하고 새 태그/릴리즈로 게시한다. 정확한 기준 커밋, 배포 파일 해시, CI와 설치 증거를 연결한다.

`build/`는 Git에서 제외된다. 기존 사용자 설정 백업/PIN 해시가 포함될 수 있으므로 폴더 전체를 Git에 추가하거나 외부 공개하지 않는다.

빌드 및 통합 시험 예시:

```powershell
dotnet build src/WinUI3/WindowsAppProtector.WinUI.csproj --no-restore -c Release -p:Platform=x64
git diff --check

# 현재 dist 파일을 다시 생성하므로 공개 파일 보존본과 혼동하지 말 것.
.\build_distribution.ps1

dotnet publish tests/ProcessCloseIntegration/ProcessCloseIntegration.csproj -c Release -r win-x64 --self-contained true -o build/process-close-integration
.\build\process-close-integration\ProcessCloseIntegration.exe build/process-close-result.json
.\build\process-close-integration\ProcessCloseIntegration.exe --discovery build/discovery-result.json

# 공유 VM 접속·읽기 전용 확인. 현재 SMB 작업 상태 확인이 선행돼야 한다.
.\build\vm-qa-beta6-final\Invoke-WapVM.ps1 -Os Windows10 -Action Inspect
```

시험 드라이버의 `Prepare`, `Sync`, `Install`, `Task`, `Feature` 등은 변이를 일으킨다. `SeedFixture`는 시험 계정의 WAP 설정을 시험 앱 목록으로 바꾸므로 **실사용 Windows 11 Admin 계정에는 실행하지 않는다**. Admin의 실제 보호 앱 9개와 PIN을 보존한다.

게스트 Windows PowerShell 5용 `Guest-*.ps1`은 UTF-8 BOM으로 저장한다. `SyncScripts`와 `Sync`의 차이, 고정 경로, 기존 체크포인트 존재 여부를 먼저 읽는다. 두 OS의 호스트 파일 복사를 동시에 실행하면 공유 경로 복사 경쟁이 생길 수 있다. 드라이버의 실행 중 SMB 작업 검사만으로 전체 SMB 시험 종료를 단정하지 않는다.
