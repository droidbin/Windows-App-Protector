# Windows App Protector 차기 버전 로드맵

- 작성일: 2026-11-08
- 기준 버전: 1.3.0 (`v1.3.0`, master `4e7b077`)
- 관련 문서: [REVIEW-2026-11-06.md](REVIEW-2026-11-06.md). 이 문서는 그 보고서 6절의 2·3단계를 버전 단위로 나누고, My Lockbox 대체에 필요한 기능을 더한 것이다.
- 버전 규칙: 메이저 1 단위, 마이너 0.1 단위, 버그 수정 0.001 단위(세 번째 자리)

## 요약

| 버전 | 성격 | 핵심 | 예상 규모 |
|---|---|---|---|
| 1.3.1 | 버그 수정 | 백그라운드 먹통의 남은 원인 제거, 숨긴 창 복구 | 1~2일 |
| 1.4.0 | 마이너 | PIN 변경, Win+L·절전 시 재잠금, 트레이 메뉴, 이벤트 기반 창 감시, 로그 | 약 1주 |
| 2.0.0 | 메이저 | **실행할 때 PIN을 묻는 My Lockbox 방식**(확정), 서비스 중심 구조, 우회 차단, 앱별 정책 | 3~4주 |
| 상시 | 배포·운영 | 바이너리 Git 보관 중단, 테스트·CI 강화 (코드 서명은 제외 확정) | 병행 |

1.3.0은 "프로그램이 꺼지거나 먹통이 되는" 문제를 우선 막은 버전이다. 하지만 이 앱은 아직 **"앱을 아예 못 쓰게 막는 도구"**이고, **"실행할 때 비밀번호를 묻는 도구"(My Lockbox)**는 아니다. 이 차이를 메우는 것이 2.0의 목표다.

## 1. 1.3.1 — 버그 수정

| 항목 | 내용 | 근거 위치 |
|---|---|---|
| 창 감시 멈춤 제거 | 다른 프로세스 창을 숨기고 보일 때 쓰는 동기 `ShowWindow`를 `ShowWindowAsync`로 바꾼다. 보호 대상 앱이 응답 없음 상태여도 WAP UI가 함께 멈추지 않는다. 1.3.0 이후 남은 **먹통의 주요 원인**이다. | `MainWindow.xaml.cs` `HideLockedAppWindows`, `RestoreHiddenProtectedWindows` |
| 트레이 아이콘 갱신 방식 | 700ms마다 Explorer에 `Shell_NotifyIcon`을 동기 호출하는 대신, Explorer가 재시작될 때 오는 `TaskbarCreated` 메시지를 받았을 때만 다시 등록한다. | `MainWindow.xaml.cs` `EnsureTrayIcon`, `MessageWndProc` |
| 숨긴 창 영구 실종 방지 | 숨긴 창 정보(핸들·PID)를 파일로 저장한다. WAP가 비정상 종료돼도 다음 실행이나 제거 시 복구한다. "브라우저가 안 열린다"는 증상을 막는다. | `MainWindow.xaml.cs` `hiddenProtectedWindows` |
| 종료 대상 판정 | 잠글 때 앱을 종료하는 대상을 전체 경로로만 찾는다. 지금은 이름이 같은 다른 경로의 exe도 종료할 수 있다(인계서 설명과 다름). | `ProtectedAppProcessService.cs` `CloseRunningAppsAsync` |

## 2. 1.4.0 — 편의·안정성

| 항목 | 내용 | 기대 효과 |
|---|---|---|
| **PIN 변경 기능** | 지금은 설정 창에 PIN 변경이 **없다**(`SettingsDialog.xaml.cs`). 기존 PIN 확인 → 새 PIN 두 번 입력 순서로 추가한다. | 기본 기능 공백 해소 |
| 즉시 재잠금 | Win+L, 절전, 사용자 전환 시 보호 앱 전체와 관리 화면을 바로 잠근다(`WTSRegisterSessionNotification`, `WM_POWERBROADCAST`). | 자리를 비울 때 유휴 시간을 기다리지 않음 |
| 트레이 메뉴 | 우클릭 시 열기 / 전체 잠금 / 종료(PIN 필요) 메뉴를 띄운다. 지금은 우클릭도 창 열기만 한다. | 사용성 |
| 이벤트 기반 창 감시 | 700ms 주기로 모든 창을 훑는 대신 `SetWinEventHook`으로 창이 나타나거나 앞으로 올 때만 검사한다. | CPU 사용 감소, 잠긴 창이 잠깐 보이는 현상 감소 |
| 진단 로그 | 잠금·해제·인증 실패·타이머 지연을 순환 로그(용량 제한)로 남긴다. | "먹통" 문의를 재현 없이 분석 |
| 잠금 이력 화면 | 차단된 실행 시도와 PIN 실패 시각을 보여 준다. | 누가 몰래 열려 했는지 확인 (My Lockbox 대비 차별점) |

## 3. 2.0.0 — My Lockbox 방식 전환 (핵심 권장안)

### 3-1. 사용 흐름 비교

| | 현재 (1.3.0) | 2.0 목표 |
|---|---|---|
| 잠긴 앱 실행 | "차단되었습니다" 안내 후 끝. 실행 경로에 따라 UAC 창이 뜨거나 조용히 실패 | **PIN 창 → 맞으면 바로 실행** |
| 잠긴 앱을 쓰려면 | WAP 열기 → PIN → 해제 → 앱 실행 → (유휴 시간이 지나야) 재잠금 | 앱 아이콘 더블클릭 → PIN |
| 재잠금 | 유휴 시간 또는 수동 | 앱을 닫으면 자동 (또는 허용 시간 경과) |

### 3-2. 구성

```
[보호 앱 실행] → IFEO Debugger → WAP.Gate.exe (asInvoker, PIN 창)
                                       │ Named Pipe (호출자 SID·PID 검증)
                                       ▼
                         WindowsAppProtectorService (SYSTEM)
                         - 잠금 상태·허용 토큰·시도 횟수 단독 소유
                         - 인증 성공 시 원래 exe를 IFEO 우회로 실행
                         - 세션별 창 감시 에이전트 기동·재기동
                                       ▲
                         WAP UI (관리 화면, 설정만 담당)
```

| 항목 | 내용 | 해결되는 문제 |
|---|---|---|
| **Launch Gate** | IFEO `Debugger`를 관리자 권한이 필요 없는 경량 `WAP.Gate.exe`로 바꾼다. 지금은 `requireAdministrator`인 UI 본체를 가리킨다(`ProtectionService.cs`, 서비스의 `SyncRules`). | 실행 시 PIN 입력, 잠긴 앱 실행 시 UAC 창 |
| 서비스 중심 상태 | 잠금 상태와 PIN 시도 횟수를 서비스가 소유하고 디스크에 영속 저장한다. UI와 Gate는 요청만 보낸다. IFEO 규칙 쓰기도 서비스 한 곳으로 모은다(지금은 UI와 서비스에 중복). | UI를 강제 종료하면 보호가 풀림, 재시작하면 시도 제한이 초기화됨 |
| PIN 저장소 일원화 | PIN 해시와 보호 목록은 ProgramData(관리자·SYSTEM 전용)에만 둔다. 사용자 폴더의 `config.json`·`pin.json`은 마이그레이션 후 제거한다(`JsonSettingsStore.cs`). | 사용자 폴더 파일을 지우면 PIN이 초기화되는 우회 |
| 실행 파일 식별 강화 | 경로·해시(선택적으로 서명자)로 식별한다. IFEO는 파일 이름 기반이라, 이름을 바꿔 실행하는 경우를 프로세스 생성 감시(ETW 등)로 보완한다. | exe 이름만 바꿔 실행하는 우회 |
| 세션 감시 에이전트 | 브라우저 창 숨김 기능을 서비스가 관리하는 사용자 세션 에이전트로 옮긴다. 에이전트가 죽으면 서비스가 다시 띄운다. | WAP UI가 꺼지면 브라우저 잠금이 풀림 |
| 앱별 정책 | 앱별 PIN, 허용 시간(예: 30분), 종료 즉시 잠금, 시간대별 잠금 | 사용 시나리오 확장 (2.0 포함 확정) |

### 3-3. 마이그레이션
- 1.x 설정(사용자 폴더 + ProgramData)을 처음 실행할 때 서비스 저장소로 옮긴다. PIN은 해시를 그대로 이전하므로 다시 설정할 필요가 없다.
- 설치 프로그램이 기존 IFEO `Debugger` 값을 Gate 경로로 바꾼다. 제거할 때는 모두 원복한다.

### 3-4. 위험 요소
- IFEO 우회 실행 방식은 대상 앱(자식 프로세스를 다시 띄우는 런처형 앱 등)마다 동작이 달라 호환성 시험 범위가 넓다.
- 서비스가 사용자 세션에 프로세스를 띄우려면 `CreateProcessAsUser`가 필요하다. 권한 경계를 설계할 때 보안 검토가 필요하다.

**결정 사항 (2026-11-08 확정)**
1. 2.0은 **My Lockbox 방식**(실행할 때 PIN을 묻고, 맞으면 바로 실행)으로 전환한다.
2. 코드 서명은 **하지 않는다.** 개인용 도구이므로 인증서 비용을 들이지 않는다. 4절의 코드 서명 항목과 5절 우선순위 4번은 제외한다. 업데이트 무결성은 현재처럼 GitHub SHA-256 digest 확인으로 유지한다.
3. 앱별 PIN·허용 시간·종료 즉시 잠금·시간대별 잠금 등 **앱별 정책은 2.0에 포함한다.** 2.0 예상 규모는 3~4주로 늘어난다.
