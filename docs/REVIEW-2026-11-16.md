# Windows App Protector 현행 문제점 및 차기 버전 개선 보고서

2026-11-16 KST · 공개 안정판 1.3.0 및 개발 후보 1.3.1-beta.1

## 요약

**1.3.1의 우선순위는 잠금 상태 저장과 창 복구의 신뢰성이다.** 설치된 1.3.0의 로그에 전체 잠금 단축키 처리 중 PIN 백업 파일 교체가 실패한 예외가 두 건 남아 있다. 설정 저장을 직렬화하고, 화면의 잠금 상태가 저장된 정책과 실제 차단 상태에 일치하는지 먼저 확인해야 한다. [근거 1·3](#근거와-재검증)

1.3.1-beta.1은 응답 없는 앱의 창을 비동기 처리하고 Explorer 재시작 시 트레이 아이콘을 복구하도록 개선했다. Release x64 빌드는 경고·오류 없이 통과했다. 다만 현 소스로 새로 게시한 종료 통합 시험에서 정상 종료 대상이 닫히지 않았고, 숨긴 창 복구와 Explorer 재시작은 실제 UI에서 확인하지 못했다. **아래 출시 기준을 충족할 때까지 베타 초안의 공개와 안정판 승격을 보류할 것을 권고한다.** [근거 2·4·5](#근거와-재검증)

[5](#근거와-재검증) | **1.3.1.** 대화형 Windows 세션에서 픽스처의 PID·창 핸들·종료 요청 결과를 기록해 원인을 좁힌다. 동일 경로 정상 종료, 같은 이름·다른 경로 및 패키지 앱 제외, 종료 거부 시 5초 대기 후 생존을 재검증한다. 경로를 읽을 수 없는 프로세스는 건너뛰고 이름만으로 종료하는 동작을 되살리지 않는다. |

IFEO 실행 차단은 파일명으로 판정해 같은 이름의 다른 앱까지 막을 수 있으며, 브라우저 창 감시는 UI 종료 시 중단된다. 코드 검토에서 확인한 구조이며 우회 동작의 실기 재현은 범위에 포함하지 않았다. [3·4·6](#근거와-재검증) | **2.0.0.** 서비스가 PIN 해시, 잠금 상태와 실패 제한을 소유하도록 옮기고 인증·정책 변경 요청의 호출자와 세션을 검증한다. 사용자 설정 파일 변조와 UI 재시작에도 PIN·정책·실패 제한이 유지되고, 같은 이름의 비대상 앱 및 다중 세션에 영향을 주지 않는지 검증한다. |

[4·7](#근거와-재검증) | **1.3.1**에서 Explorer 재시작 후 아이콘 한 개와 클릭·단축키 동작을 확인한다. **1.4.0**에서 세션 이벤트 즉시 재잠금, 기존 PIN 확인을 거치는 PIN 변경, 이벤트 중심 창 감시와 누락 보완 검사, 트레이 메뉴, 용량 제한이 있는 로컬 로그를 추가한다. | **높음 · 출시 검증 공백** | CI는 패키지를 생성하고 파일 존재·해시를 확인한다. 종료 통합 시험·설치·업그레이드·재부팅 시험 결과는 이 워크플로의 성공 상태에 포함되지 않는다. [2](#근거와-재검증) | **1.3.1.** CI에 자동 실행 가능한 설정·버전 비교·업데이트 해시 검사를 추가하고, 대화형 VM 시험 결과를 후보 커밋 및 배포 파일 해시와 연결한다. 안정판 게시 전 아래 출시 기준을 확인한다. |

## 1.3.1 출시 기준과 후속 버전

1. **잠금 상태 일관성.** 동시 저장 및 저장 실패 시험을 통과한다. 재시작과 서비스 재동기화 후 PIN·보호 목록·차단 상태가 저장된 정책과 일치한다.
2. **백그라운드 실기 검증.** Windows 10·11 x64 테스트 환경에서 응답 없는 보호 앱이 있어도 트레이와 단축키가 동작한다. 앱별 해제·강제 종료 복구·업그레이드와 제거·Explorer 재시작 시험을 통과한다. 프로세스 종료 통합 시험도 같은 환경에서 통과한다.
3. **배포 검증.** 동일 후보 패키지로 클린 설치 UI·PIN, 1.3.0에서 업그레이드 시 설정 보존, 실제 재부팅 후 자동 시작을 확인한다. 업데이트 시험은 정상 SHA-256 자산의 설치와 해시 누락·불일치 자산의 실행 차단을 확인한다. 배터리 전환 시 상주 여부는 배터리 장치에서 별도로 검증한다. 각 결과에 OS 빌드·커밋·패키지 해시·통과 여부를 기록한다.
4. **공개 순서.** 베타 공개 전 1·2번과 클린 설치·업그레이드 기본 시험을 마친다. 안정판은 전체 검증을 통과한 별도 버전의 해시를 확인한 뒤 게시한다. 코드 서명을 도입하지 않는 기존 결정에 따라 SHA-256 검증을 유지한다. 릴리스 계정이 탈취되어 자산과 해시가 함께 바뀌는 위험은 남는다. [2·6·7](#근거와-재검증)

**1.4.0**에서는 자리 비움과 복귀 시의 잠금 동작, PIN 관리, 트레이 조작과 진단을 개선한다. **2.0.0**에서는 보호 앱 실행 시 PIN을 받아 승인된 실행만 허용하는 My Lockbox 방식으로 전환한다. 서비스와 실행 게이트 간 IPC를 도입하고 앱별 PIN·허용 시간·종료 시 재잠금·시간대 정책을 지원한다. 기존 PIN과 목록을 보존하는 마이그레이션을 먼저 시험하고, Win32·브라우저·패키지 앱별 실행 호환성과 권한 경계를 검증한 후 지원 범위를 확정한다. [6·7](#근거와-재검증)
